8. Backend Implementation Notes

🔑 Dual Scoping Pattern (Critical)

Every reporting endpoint must handle two modes:
Site-scoped: X-Site-Id header present → filter to that site only.
Claim-scoped: X-Site-Id empty → read X-Allowed-Site-Ids from auth middleware, fan out over all caller-accessible sites.

🏗️ Entity Hierarchy

Site → Contract → ContractArea → Line → TaskTemplate → TaskSchedule
                              ↘ Shift → Personnel → CoverageAssignment
                              ↘ BlackoutDate
                              ↘ AdHocTask (separate from recurring schedules)

📊 What the Backend Must Compute

  • Occurrence generation: TaskTemplates × frequency → daily occurrences across contract period, respecting Shift operating days and Blackout dates
  • Burn-down: Baseline (total expected) vs Actual (completed) over time, projected end-of-year
  • Density: Per-day occurrence counts for calendar heatmaps
  • Regeneration: Diff-based — when scope changes, compute new schedule, return { new, removed, preserved }
  • Completion: Aggregate total/completed/canceled/pending/overdue per site, by shift and category
  • Audit: Occurrence-grain cancellation rows with reason codes
  • Trend: Monthly/weekly completion % time series vs 90% target
  • Drill: Hierarchical breakdown (Site → Area → Category → Status)
  • Man-Hours: Per-area budgeted vs canceled hours

🔐 Auth Requirements

  • Cognito JWT with site_ids claim injected by PreTokenGenerator Lambda
  • X-Allowed-Site-Ids derived from JWT claims by auth middleware
  • RLS (Row-Level Security) at DB layer: SET LOCAL app.current_site_ids
  • Every endpoint validates scoping — never return cross-site data
